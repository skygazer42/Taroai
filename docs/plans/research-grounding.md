# Research Grounding Notes

This file records the source-backed terminology check for the Taroai enterprise Agent Workspace plans.

Use it before approving or expanding any plan that mentions external frameworks, protocols, sandbox providers, vector stores, observability, or frontend architecture.

## Method

1. Check primary or official sources first.
2. Inspect the current repo before writing implementation claims.
3. Separate `implemented now`, `planned boundary`, `candidate provider`, and `internal product term`.
4. If a term is vendor-specific or fast-moving, verify it again before implementation.

## Source-Backed Terminology

| Term | Source-Backed Meaning | How Plans Should Use It |
| --- | --- | --- |
| LangGraph | LangGraph is an orchestration runtime focused on durable execution, streaming, human-in-the-loop, and persistence. Checkpointers persist graph state; stores persist application-defined long-term data. | Treat as a candidate runtime adapter. Current code has `agent/graph.py` as a seam, not a verified LangGraph implementation. |
| LangChain agents | LangChain describes an agent as a model calling tools in a loop until a task is complete; its harness can include tools, middleware, guardrails, planning/delegation, and human-in-the-loop steering. | Use for agent loop vocabulary. Do not imply the current runtime already uses LangChain. |
| LlamaIndex / RAG | LlamaIndex RAG docs describe loading documents/nodes, indexing, storing, retrieving, querying, and evaluating. Retrievers fetch relevant context for a user query or chat message. | Treat as an optional knowledge/RAG adapter. Current code has a native `knowledge` package, not a verified LlamaIndex integration. |
| MCP tools | MCP tool servers expose tools that models can invoke; each tool has a unique name and metadata including input schema. | Say `MCP-compatible` or `MCP-style` until actual MCP client/server code exists. |
| E2B | E2B provides isolated cloud sandboxes where agents can run code, process data, and use tools; SDK docs describe Linux access, files/directories, commands, isolated code, and internet access. | Treat as a candidate sandbox provider behind `SandboxAdapter`, not as a committed or security-approved provider. |
| OpenAI-compatible Model Gateway | For Taroai planning, this means an internal gateway boundary with OpenAI-style request/response concepts such as model, messages or input, tools, tool choice, streaming, and usage. | Product flow calls this gateway. Direct OpenAI, OpenAI-compatible endpoints, or LiteLLM can be provider adapters behind the gateway after review. |
| Pydantic Settings | Pydantic Settings loads config classes from environment variables or secrets files; `BaseSettings` allows values to be overridden by environment variables and can load env files. | Current code aligns with this pattern. Keep backend settings and management objects as Pydantic models. |
| FastAPI exception handlers | FastAPI supports global custom exception handlers that return JSON responses, and warns against leaking internal validation details. | Current `ApiExceptionManager` is a valid direction. Plans should require new business exceptions to register manager rules, not route-level try/except blocks. |
| PostgreSQL RLS | PostgreSQL row security policies restrict which rows can be selected/inserted/updated/deleted; if row security is enabled and no policy exists, default deny applies. | Use as defense-in-depth for tenant isolation, not as the only authorization layer. |
| Redis TTL | Redis `EXPIRE` sets a timeout after which a key is automatically deleted. | Appropriate for short-term run/session memory; long-term memory needs durable storage and review policy. |
| pgvector | pgvector is an open-source Postgres extension for vector similarity search, supporting exact/approximate nearest neighbor search and multiple distance metrics. | Candidate durable vector backend. Do not claim it is chosen until Q-003 is answered. |

## Implementation Wording Rules

- Write `candidate provider` when discussing E2B, LiteLLM, pgvector, or LlamaIndex before a review decision exists.
- Write `adapter seam` when current code has only config or package boundaries.
- Write `MCP-compatible manifest` unless an actual MCP protocol implementation is added.
- Write `OTel-compatible trace model/export boundary` until full instrumentation and live collector deployment are implemented.
- Write `in-memory foundation` only for services without durable or external-adapter persistence; memory now has Redis-backed short-term put/get/list/delete/tenant-delete and SQLite-compatible long-term persistence plus tenant redaction foundations.
- Write `OpenAI-compatible Model Gateway` for model flow.
- Use `tests-only fixture adapter` only in test sections, fixtures, or contract-verification sections.
- Do not describe planned packages as implemented.
- Do not treat vendor docs as a security approval; sandbox, model, vector, and connector providers still need security review.
